## 推奨ツールスタック

| レイヤー | ツール | 月額コスト | 自動化レベル |
|--------|-------|----------|------------|
| オーケストレーション | n8n (self-hosted) | 無料 | ★★★★★ |
| AI 全般 | Claude API (Sonnet 4.6) | ~$30 | ★★★★★ |
| 調査 | Perplexity API | $20 | ★★★★☆ |
| ニュースレター | Beehiiv (Scale) | $42 | ★★★★★ |
| ブログ | Ghost Pro | $25 | ★★★★☆ |
| SNS スケジュール | Buffer | $18 | ★★★★☆ |
| デジタル販売 | Ko-fi (Gold) | $8 | ★★★☆☆ |
| 画像生成 | Ideogram API | $20 | ★★★★☆ |
| 分析ダッシュボード | Google Looker Studio | 無料 | ★★★★☆ |
| **合計** | | **~$163/月** | |

> Substackではなく**Beehiiv**を選ぶ理由: SubstackはAPIが極めて限定的で自動化が困難。
> Beehiivは完全なREST APIを持ち、n8nとの連携が容易。

## 各部隊の詳細設計

### 1. 司令塔（オーケストレーター）

**役割**: 全部隊のスケジューリング・優先度管理・ボトルネック検知

**自動化フロー**:
```
毎朝 9:00 → n8n が起動
  ├── 今日の候（こう）を確認（72候カレンダーDB参照）
  ├── 公開予定コンテンツのステータス確認
  ├── 調査部隊に本日のトピックを指示
  └── 前日のKPI（ビュー・収益）をSlack/メールで通知
```

**人間がやること**: 週1回のSlack通知を3分で確認するだけ

---

### 2. INPUT LAYER

#### 2a. トレンド監視部隊

**役割**: 旬なトピックを自動発見し企画部隊に渡す

```
自動フロー（毎日）:
  Google Trends API
  + RSS (NHK World, Japan Times, Nippon.com)
  + X/Twitter API (キーワード監視)
        ↓
  Claude API でスコアリング
  「このテーマは今週の候と関連するか？収益化しやすいか？」
        ↓
  スコア上位3件をNotion/Airtableのトレンドキューに追加
```

#### 2b. 読者信号収集部隊

**役割**: 読者の反応から次のコンテンツニーズを発見

```
収集源:
  - Beehiiv メール開封率・クリック率
  - Ghost コメント・シェア数
  - Buffer エンゲージメント率
        ↓
  週次でClaude APIが分析レポート生成
  「先週最も反応が良かった候: 蛙始鳴（開封率42%）」
```

---

### 3. PRODUCTION PIPELINE

#### 3a. 調査部隊

**役割**: 各候・テーマの一次情報収集

```
トリガー: 司令塔から「今週の候: ○○」を受信
        ↓
Perplexity API で自動調査:
  - 候の意味・歴史的背景
  - 関連する日本の行事・食材・文化
  - 海外での検索需要（Googleトレンド）
  - 競合記事の構成分析
        ↓
調査レポート（Markdown）を content/[theme]/drafts/ に保存
```

#### 3b. 企画部隊

**役割**: 調査レポートをもとに記事構成を生成

```
トリガー: 調査レポートの保存を検知
        ↓
Claude API で記事構成を生成:
  - ターゲット読者（ペルソナ参照）
  - タイトル候補 × 3
  - 見出し構成（H2/H3）
  - SEOキーワード
  - アフィリエイトリンク挿入箇所
  - 推奨文字数・画像数
        ↓
企画書を drafts/ に追記保存
```

**72候専用の自動スケジュール**:
```
72候は年間スケジュールが固定 → コンテンツカレンダーが自動生成可能

1月6日:  芹乃栄（せりすなわちさかう）
1月11日: 水泉動（しみずあたたかをふくむ）
...（72候すべて事前登録）

→ 各候の5日前に調査部隊が自動起動
```

#### 3c. 執筆部隊

**役割**: 企画書から完成記事を生成

```
トリガー: 企画書が承認済みステータスに変更
        ↓
Claude API (Opus 4.7) で本文生成:
  - System prompt: 「あなたは日本在住の日本人として、
    海外の読者に日本の季節の知恵を伝えるライターです。
    一人称の体験を必ず含め、翻訳ではなくオリジナルの
    視点で書いてください。」
  - 企画書の構成に沿って生成
  - 品質チェック（文字数・構成・読みやすさ）
        ↓
品質ゲート（Claude APIで自動評価）:
  □ 800〜1500語か
  □ 日本人の一次情報が含まれているか
  □ SEOキーワードが自然に含まれているか
  □ アフィリエイトリンク挿入箇所があるか
  → スコア80点以上で次工程へ / 以下は自動修正リトライ
        ↓
完成記事を drafts/ に保存（frontmatterつき）
```

#### 3d. リパーパス部隊

**役割**: 1記事 → 6フォーマットに自動展開

```
トリガー: 完成記事の保存を検知
        ↓
Claude APIが6つのフォーマットを並列生成:

  ① Beehiivニュースレター版（本文の要約＋CTA）
  ② Twitterスレッド（8〜12ツイート）
  ③ Instagramカルーセル（スライド構成 5〜10枚）
  ④ Ko-fi PDFガイド（テンプレート or 詳細版）
  ⑤ TikTokスクリプト（60秒）
  ⑥ KaryaKarsa版（インドネシア語に要約翻訳）
        ↓
各フォーマットを repurposed/ に保存
Ideogram APIで各フォーマット用の画像を自動生成
```

### 4. DISTRIBUTION LAYER

#### 4a. 投稿部隊

**役割**: 各プラットフォームへの自動投稿

```
公開スケジュール（例: 候の当日）:

  Day 0 (候の初日):
    6:00  → Beehiiv ニュースレター送信
    8:00  → Ghost ブログ公開
    12:00 → Twitterスレッド投稿
    18:00 → Instagram カルーセル投稿

  Day 2:
    → Ko-fi PDFをアップロード・告知

  Day 4:
    → KaryaKarsa 記事公開（インドネシア語）

  Day 5 (次の候の前日):
    → 「次の候」のティーザー投稿（SNS）
```

**APIの使い方**:
```
Ghost API → 記事自動公開
Beehiiv API → ニュースレター送信
Buffer API → Twitter/Instagram スケジュール投稿
Ko-fi → 手動 or Zapier連携（APIが限定的）
```

#### 4b. 読者関係部隊（CRM）

**役割**: 購読者との関係を自動で深める

```
Beehiiv 自動シーケンス:
  購読直後:
    Day 0: ウェルカムメール（日本人であることの自己紹介）
    Day 3: 「なぜ72候なのか」ストーリーメール
    Day 7: 最初の有料コンテンツ案内

  継続購読者:
    毎月: 翌月の候カレンダーPDF送付
    毎季: 季節特集（春夏秋冬）有料号の案内

  離脱防止:
    30日未開封 → 「久しぶりに」リエンゲージメントメール
    90日未開封 → 解除確認メール
```

### 5. OPTIMIZATION LAYER

#### 5a. 分析部隊

**役割**: 全プラットフォームのKPIを自動集計・レポート化

```
週次自動レポート（毎週月曜朝）:
┌──────────────────────────────────┐
│ 先週のパフォーマンスサマリー         │
├──────────────────────────────────┤
│ 最高パフォーマンス候: 蛙始鳴        │
│  - Beehiiv 開封率: 42.3%          │
│  - Ghost PV: 1,247               │
│  - Twitter インプレ: 28,400       │
│  - Ko-fi 売上: $47               │
├──────────────────────────────────┤
│ 改善が必要な候: 土潤溽暑            │
│  - 開封率: 18.1%（平均-12%）       │
│  - 推定原因: タイトルが弱い          │
│  - 推奨: A/Bテストで件名を変更      │
└──────────────────────────────────┘
```

**集計対象KPI**:
- メール開封率 / クリック率
- ブログPV / 滞在時間 / 離脱率
- SNSインプレ / エンゲージメント率
- Ko-fi / Gumroad 売上
- アフィリエイト収益

#### 5b. マネタイズ最適化部隊

**役割**: 収益を最大化するための自動調整

```
月次で自動実行:
  □ アフィリエイトリンクのCTR確認→低いリンクを差し替え候補リスト化
  □ Ko-fi PDFの価格帯分析→売れ筋価格を調整
  □ 無料/有料コンテンツ比率の最適化
  □ 季節商品（前の季節が終わる前に次の季節を告知）のタイミング最適化
```
