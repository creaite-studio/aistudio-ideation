## 1. プロダクト概要

### What
Phase 3で蓄積したデータ（キャラ・関係・伏線・知識状態・シーンメモ）をAIが読み取り、**人間が見落とす矛盾や、新しい物語の可能性**を提示する。

### Why（解決する壁）
- Q3で挙がった「物語の方向性を決めること」「絡み合う伏線の管理」を、AIが補助することで一段引き上げる
- 複雑な世界観を一人で管理する限界を超える

### 差別化の一言
「複雑な世界観を、AIが一緒に育ててくれる」

## 2. スコープ

### Phase 4に含むもの ✅

## 3. 機能仕様

### 3-1. 矛盾チェック

```
- トリガー:
  - シーンメモ画面に「矛盾チェック」ボタン
  - 押下時、現在のシーン本文 × 同エピソードまでの知識状態をAIに送信
- AIへの入力プロンプト構造:
  - 物語の登場人物リスト + 各キャラの該当時点の知識状態
  - シーン本文
  - 場所・組織情報（関連分のみ）
- AIの出力:
  - 矛盾リスト（例: 「シーン3でAは"Bが裏切り者"と発言していますが、A は2話時点でこの情報を知らないことになっています」）
  - 各矛盾に「該当箇所」「想定される原因」「修正候補」を提示
- ユーザー操作:
  - 矛盾を「無視」「修正済」「未対応」でステータス管理
```

### 3-2. 伏線サジェスト

```
- トリガー:
  - キャラクター詳細パネル or 関係エッジ詳細パネルに「伏線案を出す」ボタン
- AIへの入力:
  - 対象キャラ/関係の設定情報
  - 既存の伏線一覧（重複回避のため）
  - プロジェクトのジャンル・テーマ
- AIの出力:
  - 3〜5個の伏線案（例:「Aの過去に、Bと面識があった事実を後で明かす」）
  - 各案に「効果」「仕込みやすい話数」「回収のヒント」
- ユーザー操作:
  - 気に入った案を「伏線として追加」ボタンで伏線トラッカーに登録
```

### 3-3. プロット方向性提案

```
- トリガー:
  - プロジェクト詳細画面に「物語の方向性を考える」ボタン
- AIへの入力:
  - プロジェクトのジャンル・テーマ・メモ
  - 登場キャラ・場所・組織の概要
- AIの出力:
  - 物語の方向性を3〜5案提示
  - 各案に「物語のフック」「主要な対立軸」「想定される転換点」「対象読者層」
- ユーザー操作:
  - 気に入った方向性を「採用」→ プロジェクトメモに反映、エピソード雛形を自動生成可
```

### 3-4. キャラクター動機分析

```
- トリガー:
  - キャラクター詳細パネルに「動機を分析」ボタン
- AIへの入力:
  - 該当キャラの設定（説明・属性・関係・知識状態）
  - 該当キャラが登場するシーン本文（複数）
- AIの出力:
  - 想定される行動原理・モチベーション
  - 「設定と行動の不整合」がある場合は指摘
  - 物語上で動機を強化するアイデア
```

### 3-5. 課金・サブスク管理

```
- 無料プランで使える範囲:
  - MVP〜Phase 3の全機能
  - AI機能は月3回までトライアル可能
- 有料プラン（月額500円 or 980円）:
  - AI機能の使用回数制限なし（または月50回上限）
  - エクスポート機能（Phase 5で追加予定）
  - 高度なグラフ機能
- 実装:
  - Stripe Checkout で決済
  - Supabase上で `subscriptions` テーブルを管理
  - フロントでプラン情報を取得し、機能の利用可否を判定
```

## 5. 技術スタック追加

| カテゴリ | 技術 | 用途 |
|---------|------|------|
| AI API | Anthropic Claude API | 矛盾チェック・伏線サジェスト・動機分析（テキスト分析の質が高い） |
| 決済 | Stripe | 月額サブスクリプション |
| バックエンド | Supabase Edge Functions | AI APIキーを安全に扱う・Stripe Webhook受信 |

**Edge Functionの理由:** AIのAPIキーをフロントに置けないため、Supabase Edge Functions経由でClaude APIを呼ぶ。

## 6. 設計上の検討事項

### 6-1. AIへのコンテキスト量
- プロジェクトが大きくなると登場人物・関係数が膨大になる
- **方針:**
  - 矛盾チェック: 対象シーンに登場するキャラのみ + そのキャラの知識状態に絞る
  - 伏線サジェスト: 対象キャラ/関係の周辺ノードのみ
  - プロンプト長を超えないよう、要約・選別ロジックをアプリ側で実装

### 6-2. AI結果の信頼性
- AIが100%正確ではないことを前提とする
- 「AIの提案」として表示し、ユーザーが採用/却下する形に統一
- 過去のAI結果を `ai_results` に保存し、ユーザーが「なぜこう判定したか」を後で見返せるようにする

### 6-3. コスト管理
- Claude API呼び出しコストはユーザー数に比例して増える
- 無料プランは月3回までで体験のみ提供
- 有料プランでも月50〜100回程度の上限を設けて青天井を防ぐ
